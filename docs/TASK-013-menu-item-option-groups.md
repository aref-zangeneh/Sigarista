# TASK-013 — گروه‌های آپشن آیتم منو (اجباری/دلخواه) با کسر دقیق انبار

وضعیت: پیاده‌سازی کامل (بک‌اند + پنل ادمین + پاپ‌آپ منوی مشتری) انجام شد و تست‌های واحد سبز هستند.

---## ۱. خلاصهٔ کار

برای هر آیتم منو می‌توان گروه‌های آپشن تعریف کرد. هر گروه یا **اجباری** است («اجباری» — مشتری باید حداقل یک گزینه انتخاب کند) یا **دلخواه** (اختیاری). همهٔ گزینه‌ها یک **مبلغ افزوده** روی قیمت نهایی آیتم دارند. برای هر گزینه می‌توان **مواد اولیهٔ مصرفی** تعریف کرد که هنگام سفارش دقیقاً مانند یک دستور پخت کوچک از انبار کسر و هنگام لغو/کاهش تعداد به همان نسبت برگردانده می‌شود.

مثال مستند (لاته ۲۰۰ هزار تومان):

- گروه اجباری «درصد دانه قهوه» (تک‌انتخابی): «۱۰۰٪ عربیکا» +۱۲۰٬۰۰۰ ← قیمت نهایی ۳۲۰٬۰۰۰؛ «۷۰/۳۰ عربیکا» +۸۰٬۰۰۰.
- گروه دلخواه «سیروپ دلخواه»: «۳۰ میل سیروپ فندوق» +۵۰٬۰۰۰.

> سیستم مادیفایر جهانی (`MenuModifiers`) بدون تغییر باقی مانده — آن سیستمی است برای برچسب‌های رایگان. این سیستم جدید کاملاً مستقل است.

---

## ۲. مدل داده

 entities جدید (`Sugarista.Domain/Entities/`):

| Entity | فیلدهای کلیدی |
|---|---|
| `MenuItemOptionGroup` | `MenuItemId`, `PersianName`, `EnglishName`, `IsRequired`, `SelectionMode` (`Single`/`Multi`), `MinSelections`, `MaxSelections`, `DisplayOrder`, `IsActive` |
| `MenuItemOption` | `GroupId`, `PersianName`, `EnglishName`, `PriceDelta` (≥0), `IsDefault`, `IsActive`, `DisplayOrder` |
| `MenuItemOptionIngredient` | `OptionId`, `IngredientId`, `Quantity` (در واحد خود ماده اولیه، مثلاً گرم/میلی‌لیتر) |

همه با `DeleteBehavior.Cascade` به آیتم منو وصل‌اند؛ حذف آیتم، کل پیکربندی را پاک می‌کند. مایگریشن: `AddMenuItemOptionGroups` (۳ جدول جدید + دو ستون روی `OrderLines`).

### روی خط سفارش (`OrderLine`)

- `OptionLabels` (`text[]`) — برچسب فارسی گزینه‌های انتخاب‌شده برای نمایش در سبد/رسید/پنل ادمین.
- `OptionsJson` (`text`) — **اسنپ‌شات غیرقابل تغییر** از انتخاب‌ها: هر گزینه (گروه، نام، مبلغ), جمع `OptionsTotal`, و مصرف دقیق هر مادهٔ اولیه. منطق همان `CustomizationJson` نوشیدنی‌ساز است: اگر ادمین بعداً گزینه را حذف یا قیمتش را عوض کند، کسر/برگرداندن انبار سفارش‌های **ثبت‌شده** دچار خطا نمی‌شود.

---

## ۳. اعتبارسنجی و قیمت‌گذاری سرور

`Sugarista.Application/MenuItems/OptionGroups/MenuItemOptionPricing.cs`:

- گروه‌های غیرفعال نادیده گرفته می‌شوند؛ انتخاب گزینهٔ ناموجود/غیروابسته به آیتم با `DomainException` رد می‌شود.
- حداکثر/حداقل انتخابِ هر گروه چک می‌شود؛ گروه اجباری که برایش گزینه‌ای نفرستاده شده خطای فارسی می‌دهد («انتخاب حداقل یک گزینه از «…» الزامی است»).
- قیمت همیشه **سرویس‌محور** است: `resolved.UnitPrice + snapshot.OptionsTotal`؛ قیمت فرستادهٔ کلاینت فقط برای نمایش است و با `EnsurePricesHaveNotChanged` (کد `price_changed`) دوباره کنترل می‌شود.
- مصرف موادِ گزینه‌های انتخاب‌شده، per line تجمیع و در اسنپ‌شات ذخیره می‌شود.

### چک موجودی پیش از ثبت (Checkout)

`EnsureOptionIngredientsAreAvailableAsync` در `CreateOrderCheckoutCommand` تقاضای کل سبد را per ingredient جمع می‌زند و با `InventoryStocks` می‌سنجد. کمبود با `item_unavailable` و `reason: insufficient_option_ingredient` + نام گزینه برمی‌گردد تا تم مشتری پیام دقیق نشان دهد.

## ۴. کسر/برگرداندن انبار

`Sugarista.Application/Inventory/Services/MenuItemOptionInventoryService.cs` (اسنپ‌شات‌محور، الگوی `RecipeInventoryService`):

- در کسر خط (`OrderInventoryService.DeductInventoryForOrderLinesAsync`)، تغییر تعداد بیشتر (`ApplyLineQuantityChangeAsync`) → کسر `Quantity مصرف × تعداد`.
- در برگرداندن خط (لغو سفارش / کاهش تعداد) → بازگردانی دقیق همان مقدارهای اسنپ‌شات.
- با `stock.Deduct/Restore` + `InventoryLotAllocator.DeductAsync/RestoreAsync` و ثبت `StockMovement` — دقیقاً مانند اقلام پایه.

## ۵. API

### ادمین (full-replace بر سند کامل)

```
GET  /api/admin/menu-items/{menuItemId}/option-groups   → MenuItemOptionGroupsDto
PUT  /api/admin/menu-items/{menuItemId}/option-groups   → 204
```

دسترسی: `MenuItems.View` / `MenuItems.Update`. پیام PUT پنل مدیریت سند کامل گروه‌ها/گزینه‌ها/سطرهای مصرفی را می‌فرستد و سرور old config را کامل پاک و new را ذخیره می‌کند.

### منوی عمومی

`GET /api/menu` → هر آیتم فیلد `optionGroups` دارد: گروه‌های فعال با گزینه‌های فعال و **فیلد `isAvailable`** برای هر گزینه که از موجودی فعلی مواد اولیه محاسبه می‌شود (تا تم، گزینهٔ «ناموجود» را غیرفعال رندر کند).

### ثبت سفارش

`items[]` فیلد اختیاری `optionIds: [guid]` می‌پذیرد.

## ۶. UI پنل مدیریت

`Sugarista-Admin/src/components/MenuItemOptionGroupsPanel.jsx` — داخل صفحهٔ «آیتم‌های منو»:

- انتخاب آیتم → لود سند `option-groups`؛ کارت گروه با شماره، نام فارسی/انگلیسی، بج «اجباری/دلخواه»، حالت تک/چندانتخابی، حداقل/حداکثر، ترتیب (↑↓)، فعال/غیرفعال.
- هر گزینه: نام، مبلغ افزوده، پیش‌فرض، فعال، و سطرهای «مادهٔ اولیهٔ مصرفی» (انتخاب ماده + مقدار بر حسب واحد آن).
- ذخیره با دکمهٔ «ذخیرهٔ گروه‌های آپشن» و PUT کامل؛ اعتبارسنجی سمت کلاینت همان قوانین سرور است و خطا با پیام دقیق نمایش داده می‌شود.

## ۷. UI منوی مشتری (تم)

مودال «افزودن به سبد» (`Sugarista-Theme/index.html` + `app.js` + `style.css`):

- بخش «گروه‌های آپشن» بالای سازندهٔ نوشیدنی: گروه‌های **اجباری اول** با بج «اجباری» و سایهٔ رنگ، سپس «دلخواه».
- تک‌انتخابی = کارت‌های رادیویی (دایرهٔ توخالی که هنگام انتخاب پر می‌شود)، چندانتخابی = chips با «+ مبلغ».
- هر گزینهٔ فروش‌رفته (`isAvailable=false`) غیرفعال با برچسب «ناموجود».
- **قیمت زندهٔ مودال** همیشه `قیمت سایز + جمع آپشن‌ها + اجزای سازندهٔ نوشیدنی` است؛ جمع گزینه‌ها هم جدا نمایش داده می‌شود.
- خطای گروه اجباری انتخاب‌نشده به‌صورت inline (banner قرمز) زیر گزینه‌ها، بدون alert.
- سبد: سطر هر خط `optionLabels` را جدا از مادیفایرها نشان می‌دهد؛ `cartKey` شامل شناسهٔ گزینه‌هاست (پس سفارش با آپشن متفاوت، خط متفاوت است).
- checkout: `items[].optionIds` به سرور می‌رود.

## ۸. تست‌ها و E2E

- `MenuItemOptionPricingTests` (۹ تست): اضافه شدن مبلغ، گروه اجباری خالی، گزینهٔ ناشناس، پیش‌فرض, maxSelections، تجمیع مصرف مادهٔ مشترک، round-trip اسنپ‌شات، JSON نامعتبر.
- کل مجموعه: **۱۰۱ تست Application + ۹۲ تست Domain سبز**.
